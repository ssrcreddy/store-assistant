AI Assistant Components

What already exists, what the project adds, and where the AI layers sit, for the assistant built on the existing Order, Inventory and Payment APIs.

Existing legacy system New platform component New AI layer External SaaS
No legacy system changes. Everything new sits between the channels and the existing APIs, and the AI layers reach those APIs only through the tool adapter, which enforces the user's identity, authorization and PII handling.

Request path

  1. The gateway authenticates the user and forwards the message to the orchestrator.
  2. The PII redactor replaces personal data with placeholders; real values go to the vault.
  3. The response cache answers repeat questions without an LLM call.
  4. The intent router picks a path: template (no LLM), Haiku, or Sonnet.
  5. The agent loop plans the answer, using registered prompts and the knowledge base.
  6. The LLM gateway checks the budget, then calls the Claude API.
  7. The tool adapter calls legacy APIs with the user's identity; the policy engine gates write actions.
  8. The output guard re-checks for PII, restores placeholders for the owner, and streams the reply.
